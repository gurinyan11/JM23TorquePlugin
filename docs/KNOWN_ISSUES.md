# JM23 既知の問題・制約
第一期開発記録 — 2026年10月8日時点

対象車両：**MAZDA AZ-OFFROAD JM23W 7型**

## 通信・復帰
- **完全再起動後**：Torque Proの起動だけでは取得開始しない場合があり、JM23画面を開いて接続した実績があります。
- **短時間スリープ**：自動復帰の実績がありますが、バージョンによってSTART操作を要する場合もあります。
- **長時間スリープ**：自動復旧が不安定で未解決です。
- **再接続コード**：切断、Binder失効、タイムアウト、連続無応答への処理は実装されていますが、全状況での復帰を保証しません。

## Torque LiteとTorque Pro
ATOTO S8MSにはTorque Liteがプリインストールされていました。当時の環境ではJM23に必要な独自PID登録・利用機能を使用できませんでした。Torque Liteをアンインストールし、手持ちのTorque Pro APKを導入したところ、JM23の独自PID公開とダッシュボード表示が動作しました。Torque Liteの仕様全体についての断定ではありません。

## ECU項目
抽出・公開処理の存在は実車での正常動作確認を意味しません。A/F Sensor 2は高速走行時に反応した実績があります。車両メーター約80 km/hに対しTorque表示約72 km/hの差が確認されていますが、原因は未確定です。純正燃料残量、純正ODO、油温、油圧は現行のECU取得方式では未対応です。

## 通信停止時の積算
ECUデータ取得停止中の走行距離・燃料噴射量は復元できません。Tripの保存値が再起動後に復元できても、停止中の走行距離が補完されるわけではありません。

## 燃料管理
- 満タン5区間校正は実装済みですが、実給油5回による精度検証は未完了です。
- `startFuelFullTankBaseline()`は校正回数と累計値を初期化する一方、旧`fuelLitersPerOpenMinute`を初期化しません。再校正中に旧係数が推定値へ影響する可能性があります。
- 12回連続ECU無応答を停止境界の手掛かりにしており、エンジン停止の直接検出ではありません。

## 開発環境・UI
ARM64端末で当時のx86_64用`aidl`を実行できず、Java Binderクライアントで回避しました。操作画面には機能集中による改善余地があります。

これらは第一期の到達点を記録するものであり、修正計画や完成宣言ではありません。
